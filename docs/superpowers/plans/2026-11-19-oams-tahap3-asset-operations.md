# OAMS Tahap 3 (Asset Operations) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Employees master data, responsible-person history, location/responsible mutations with approval, outbound loans with return and overdue tracking, condition checks with photos, one unified asset timeline, and dashboard cards, on top of Tahap 2.

**Architecture:** New backend modules `employees`, `mutations`, `loans`; condition logs and assignment history live inside the existing `assets` module. All state changes that touch an asset run in one Prisma transaction and are audited with `entityId = assetId`, so `GET /assets/:id/history` only needs more modules in its filter. Partial unique indexes (one `PENDING` mutation, one `ACTIVE` loan per asset) are created in raw SQL in the migration. Frontend adds `/employees`, `/mutations/*`, `/loans/*`, new tabs and header actions on the asset detail page, a locked edit form, and three dashboard cards.

**Tech Stack:** as Tahap 2 (NestJS 12 ESM, Prisma 7, PostgreSQL 17, Vitest, Next.js 16, TanStack Query, react-hook-form + zod 4). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-oams-tahap3-asset-operations-design.md` (+ `docs/BLUEPRINT.md` bab 4.6–4.8, 7.5; `docs/tahap-2-core-assets.md`).

## Global Constraints

- Everything in Tahap 1 and 2 Global Constraints still applies (ESM `.js` import suffixes, `/api/v1`, error shape `{statusCode,message,errors?,path,timestamp}`, 400 `Validasi gagal.` with per-field `errors`, pagination `{data, meta}`, Indonesian copy, audit every change, no hard deletes of master data).
- "Today" is the Asia/Jakarta calendar date everywhere a date is compared (overdue, `loanedAt` not in the future).
- `PATCH /assets/:id` rejects `locationId`, `responsibleEmployeeId`, `condition` (400, per-field message `Ubah lewat mutasi` / `Ubah lewat pemeriksaan kondisi`), rejects `status` `BORROWED`/`RETURNED` (`Status ini diatur oleh peminjaman`), and rejects any `status` with 409 `Barang sedang dipinjam.` while a loan is `ACTIVE`.
- 409 messages, verbatim: `Barang sudah diarsipkan.` (existing, archived asset in any Tahap 3 action), `Barang sedang dipinjam.`, `Sudah ada mutasi yang menunggu persetujuan.`, `Kembalikan pinjaman dulu sebelum mengarsipkan.`, `Selesaikan mutasi yang menunggu dulu sebelum mengarsipkan.`, `Tidak ada perubahan yang diajukan.`, `Mutasi sudah diproses.`, `Peminjaman sudah selesai.`, `Akun ini sudah tertaut ke pegawai lain.`
- New permission codes: `employees.manage`, `loans.view`, `loans.manage`, `conditions.record`. Role matrix per spec §9. Viewer additionally gets `mutations.view` via migration SQL.
- Audit: module `employees` (`employee.created|updated|activated|deactivated`), module `assignments` (`asset.assigned`), module `condition_logs` (`asset.condition_recorded`), module `mutations` (`mutation.requested|approved|rejected|cancelled`), module `loans` (`loan.created|updated|returned`). All asset-related entries use `entityId = assetId`; `after` carries `mutationId` / `loanId` / `conditionLogId`.
- Commit after each task with the trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Never push.

## Review Focus

1. Two simultaneous `POST /loans` (or `POST /mutations`) for the same asset: exactly one succeeds, the other gets 409, no half-written rows and the asset status is consistent. Test in Task 4 (loans) and Task 3 (mutations).
2. Approving a mutation after the asset was borrowed or archived in between must fail with 409 and change nothing. Test in Task 3.
3. Returning a loan must restore the status the asset had before the loan, including `IN_USE`, and never leave `BORROWED`; a `previousStatus` of `BORROWED` falls back to `AVAILABLE`. Test in Task 4.
4. Deactivating an employee must not unassign their assets or touch active loans, and an inactive employee must be refused as new responsible, borrower or guarantor (409 `Pegawai tidak aktif.`). Test in Tasks 1, 3, 4.
5. A Petugas (no `assets.update`) must be able to attach a photo only with a valid `conditionLogId` of that asset; without it, or with a log of another asset, 403/400. Test in Task 2.
